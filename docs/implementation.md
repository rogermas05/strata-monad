## Validation commands

- `npm run check`: type checking, core/service tests, protocol tests and frontend build.
- `RUN_KURU_FORK=true forge test --root contracts --match-test testKuruDeployedFork --fork-url http://127.0.0.1:8546 -vv`: external deployed Kuru behavior, isolated inside a fork test.
- `npm run test:e2e`: real local transactions and connected browser flows; checkpoint teardown restores starting state. Do not run concurrently or hot-reload the API during the suite.
- `npm run pyth:check`: authenticated historical retrieval and read-only verifier simulation; requires user-owned provider access. No successful authentic proof run is claimed yet.

## Deployment boundaries

The local service only signs transactions on chain 31337 with a loopback RPC. Public wallet flows do not use unlocked server accounts. Controlled prices and project-funded quotes are labelled. dUSDC is a test token; WMON is backed by wrapped native tokens. The local fork is not a public testnet deployment.

Generated ABIs, deployment manifests and passing interface tests are evidence for their specific scope. They do not authenticate a Pyth payload, prove profitability or replace an external audit. No production real-money activation is authorized or claimed.
